# Executive Summary: Project Knowledge Base Setup (2026)

A project knowledge base in 2026 should be **task-organized, AI-ready, and governed by a named owner** — not a shared folder. The single biggest predictor of success is not the tool chosen but the *information architecture*: categories organized by jobs-to-be-done, no more than three levels deep, with a maintenance cadence and an assigned curator.

**Platform recommendation:** Use **Confluence** if your team is already on Atlassian/Jira — Rovo AI is bundled and Jira integration is native, putting total cost for a 20-seat team near $1,300/year. Use **Notion** for cross-functional teams that include non-technical members (marketing, ops, design) — the editor is more pleasant and the template ecosystem is unmatched, at a price of roughly $4,800/year for the same 20 seats with AI. Obsidian is preferred only for solo or privacy-critical work; SharePoint is the right default for Microsoft 365 shops already paying for Copilot.

**Why structure beats tooling:** Multiple 2026 industry analyses (Stravito, eesel.ai, Bloomfire) report that KBs mirroring the org chart see adoption collapse within two quarters, while KBs organized around user tasks survive. AI agents now consume the KB on behalf of humans, so atomic, tagged, machine-readable articles directly improve any layered RAG/Copilot/Glean experience. The most common failure mode — content decay — is solved by assigning **one named curator** per category and putting a quarterly review on the calendar.

**Rollout in three weeks:** Week 1 — define scope, success metrics, and audit existing scattered docs. Week 2 — pick the platform and set up 5–8 task-based top-level categories with a standard article template (title-as-question, prerequisites, steps, owner, last-reviewed date). Weeks 2–3 — write 10–20 seed articles addressing the highest-frequency questions surfaced in the audit; sparse but accurate beats bloated and thin. Week 3 — launch with internal "marketing" (Slack announcement, onboarding links, channel pins). Then run quarterly reviews indefinitely.

**Next steps:** (1) Confirm whether your org already has a Confluence or SharePoint license to avoid duplicate procurement. (2) Appoint a single curator before writing a line. (3) Verify current pricing and AI/API limits directly with vendors before signing. (4) If handling regulated data, confirm data-residency options with the vendor's security team.
